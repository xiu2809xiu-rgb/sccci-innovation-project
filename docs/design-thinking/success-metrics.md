# Success metrics

How we will know HuiTong works. Success metrics (SM) measure the outcomes the brief for Problem Statement #5 asks for; guardrails (GR) are limits that must hold while we chase them. Every metric is computed by HuiTong from its own records, so progress is shown in the product rather than claimed. Ids are never reused: the metrics that still hold keep their ids, reworded for #5 (SM-06, SM-08, SM-09 and every guardrail); the new ones start at SM-12 and GR-10; the rest are kept in the tag `archive/ps7-lesso-solar`.

**Status: baselines from the brief, the rest assumed.** The brief gives about an hour of consolidation and TMS entry per run, 60% of the work after an assessment, with submissions 20%, verification 10%, rework 5% and filing 5% ([A-76](../assumptions.md)). The minutes per activity below are our arithmetic on those shares (1 hour 40 minutes a run in all), and the rest are unknown until the client gives them ([Q-76](../client/questions-for-client.md)); which outcomes matter most is still open ([Q-47](../client/questions-for-client.md)). Targets are PoC targets on synthetic data, reported as laboratory estimates; real benefits can only be shown in a pilot. The summary table in [problem-statement.md](../problem-statement.md#26-success-metrics) uses the same numbers.

## Measurement protocol

The three headline measures of the final presentation, and how each is taken so the result can be repeated.

| Measure                      | What is compared                                                                                                                         | How it is measured                                                                                                                                                                                                                                                                                                                             | Linked metrics      |
| ---------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------- |
| Re-typing removed            | The current run (journey D.1) and the HuiTong run (journey D.2) for the same synthetic run                                               | List every human action in both flows from the [journey maps](journey-maps.md), and tag each as writing, tallying, typing, checking, keying, uploading, filing or a decision. Decisions, such as verifying, stay on purpose, so they are listed but not counted as removable. Report the counts before and after, with both lists as evidence. | SM-13               |
| Post-assessment time per run | Consolidating, entering, verifying and submitting a synthetic run by hand (paper, a TMS stand-in and the portal mocks), and with HuiTong | Time both from the last trainee assessed to the last submission delivered. A team member outside areas 1 to 3 does the timing. Run each method three times, alternating which goes first to even out learning, and report the median with the run size (trainees and criteria).                                                                | SM-12, SM-15, SM-16 |
| Rule set-up effort           | Writing a new synthetic course's rules by hand, and correcting and approving the rule-drafting assistant's draft                         | Time each from receiving the assessment plan to an approved rule version that decides every outcome in a test run correctly. The hand-written version is done by a team member who has not seen the draft. Report both times and what each includes.                                                                                           | SM-09, SM-14        |

**Rules for every measurement**

- **Same inputs.** Both sides use the same seeded synthetic dataset and the same scenario. The dataset and the commit measured are recorded with each result.
- **Labelled honestly.** Until the client gives real baselines ([Q-76](../client/questions-for-client.md)), every result is labelled a laboratory estimate on synthetic data. We do not claim savings at ASPRI-IPI or validated regulatory compliance.
- **Correctness beside speed.** Each result is reported with the correctness checks for the same run: outcomes matching the training manager's, duplicates prevented, records lost by sync, and the outcome of the role-based access tests.
