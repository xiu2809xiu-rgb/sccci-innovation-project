# Success metrics

How we will know HuiTong works. Success metrics (SM) measure the outcomes the brief for Problem Statement #7 asks for; guardrails (GR) are limits that must hold while we chase them. Every metric is computed by HuiTong from its own records, so progress is shown in the product rather than claimed.

**Status: baselines assumed.** Baselines come from [A-12](../assumptions.md) until the client confirms them ([Q-48](../client/questions-for-client.md)); which outcomes matter most is still open ([Q-47](../client/questions-for-client.md)). Targets are PoC targets on synthetic data; real benefits can only be shown in a pilot. The summary table in [problem-statement.md](../problem-statement.md#26-success-metrics) uses the same numbers.

## Measurement protocol

The three headline measures of the final presentation, and how each is taken so the result can be repeated. Adopted from Azri's integrated plan.

| Measure                        | What is compared                                                                                                                                     | How it is measured                                                                                                                                                                                                                                                                                                                                | Linked metrics |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------- |
| Manual steps removed           | The current flow and the HuiTong flow for the same scenario: the [hero journey](../agile/hero-journey.md) hire, and one month of SG01 and CN01 leave | List every human action in both flows from the [journey maps](journey-maps.md), and tag each as an export, a copy and paste, re-keying, a hand-off, report building or a decision. Decisions such as approvals stay on purpose, so they are listed but not counted as removable. Report the counts before and after, with both lists as evidence. | SM-05          |
| Management summary time        | Building the month's leave and payroll summary by hand in Excel, and with HuiTong, on the same synthetic month                                       | Time both from the first export to a checked summary, including review. A team member outside area 3 does the timing. Run each method three times, alternating which goes first to even out learning, and report the median with the dataset size (employees and leave records).                                                                  | SM-01, SM-07   |
| Another company's setup effort | Mapping the joining company's sample export in the wizard and importing it, and writing a bespoke parser for the same file                           | Time each from receiving the file to a correct import of every row. The parser is written by a team member who has not seen the wizard's mapping, with tests, in a controlled comparison. Report both times and what each one includes. This shows extensibility, not a production cost saving.                                                   | SM-06          |

**Rules for every measurement**

- **Same inputs.** Both sides use the same seeded synthetic dataset and the same scenario. The dataset and the commit measured are recorded with each result.
- **Labelled honestly.** Until the client gives real baselines ([Q-48](../client/questions-for-client.md)), every result is labelled a laboratory estimate on synthetic data. We do not claim corporate savings or validated regulatory compliance.
- **Correctness beside speed.** Each result is reported with the correctness checks for the same run: duplicates prevented, exceptions detected, sync failures, and the outcome of the role-based access tests.
