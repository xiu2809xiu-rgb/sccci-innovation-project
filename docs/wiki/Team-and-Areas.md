# Team and areas

Four ownership areas, so that each member owns, writes and can explain distinct code (85% of the module marks are individual).

| Area                                    | Owner              | Scope                                                                                                                        |
| --------------------------------------- | ------------------ | ---------------------------------------------------------------------------------------------------------------------------- |
| 1. Integration core and platform base   | Richie (team lead) | Connectors, the employee master, mapping, the AI mapping assistant, and the shared platform                                  |
| 2. Onboarding and approval workflows    | To be agreed in W3 | One entry onboards a new hire into SAP and INFO-TECH, intranet access after the SAP record; claims with the HQ Treasury step |
| 3. Single view, dashboards and insights | To be agreed in W3 | The single view and its dashboards, data-consistency insights, and leave consolidation with the report template and exports  |
| 4. Governance, security and monitoring  | To be agreed in W3 | Access administration, audit, PDPA and PIPL, observability, analytics, AI cost, AWS                                          |

Iok Teck, Azri and Angelyn share areas 2 to 4. Once agreed, the names go into [module-ownership.md](https://github.com/xiu2809xiu-rgb/sccci-innovation-project/blob/main/docs/team/module-ownership.md) and `.github/CODEOWNERS`, so pull requests ask the right reviewer.

Shared code (authentication, the app shell, the API client, queues, logging) belongs to area 1 and is changed through the shared-files protocol in the ownership guide.
