# Data formats of the client's systems

What each system hands HuiTong, as far as we know before the briefing call with LESSO Solar (story [A-13](agile/backlog.md#a-13-document-the-data-formats-keep-real-samples-out-of-git)). Every format below is an assumption until the client confirms it ([A-01 to A-03, A-59 to A-61](assumptions.md)); the open questions are in [questions-for-client.md](client/questions-for-client.md).

Three rules apply:

- **The mocks emulate the formats.** Each mock serves the formats named under "Emulated by" below, so the connectors and mappings are tested against the kind of file or message the client uses ([mock systems](api/mock-systems.md)). SAP-style exports, the intranet's Excel exports and Excel versions of INFO-TECH's exports are not emulated yet.
- **Every file goes through the mapping engine.** A file is read through a mapping version HR approved ([importing a file](team/area-1-integration-core.md#importing-a-file)). A real export replaces a mock one with a new mapping version, not a code change, as long as HuiTong already reads its encoding, date layout and transforms; otherwise it needs a new transformer (A-60).
- **Client samples stay out of git.** A sample export from the team's data folder is tried on a throwaway local stack from the git-ignored [`samples/`](../samples/README.md) folder, and then deleted ([trying a client's sample export](#trying-a-clients-sample-export)). Client data is never committed.

How dates, times, time zones and text encodings are read is on its own page: [dates and encodings](architecture/dates-and-encodings.md). HuiTong reads `.csv` and `.xlsx` files; a legacy `.xls` is refused, so save one as `.xlsx` or as CSV UTF-8 first.

## Another company's HR system

Another Chinese company in Singapore joins through its HR export, read by a file connector and set up by configuration, not code ([A-23](assumptions.md)). The synthetic [Malaysia sample](../apps/web/public/samples/organisation-e-malaysia-hr-export.csv) stands in for it.

| What                   | Format                                                                                                                                                                                                                                                                     |
| ---------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| File type and encoding | CSV in UTF-8 (with or without a byte-order mark) or GB18030, which covers GBK; or `.xlsx`                                                                                                                                                                                  |
| Key fields             | An employee number in the form the import requires, `E` and six digits, such as `E200101` in the Malaysia sample; a row without one is left out. The other columns are whatever the mapping maps                                                                           |
| Dates                  | The layout the approved mapping names: `YYYY-MM-DD`, `YYYY/MM/DD`, `YYYYMMDD`, `DD/MM/YYYY`, `MM/DD/YYYY` or `DD.MM.YYYY`; Excel date cells are read as dates                                                                                                              |
| Limits                 | An import takes up to 5 MB and 20,000 rows, and a workbook may unpack to 100 MB at most. The mapping wizard takes a sample of up to 1 MB and reads its first 20 rows, so cut a sample from a larger export. Both take at most 60 columns, each header up to 120 characters |
| Never kept             | National ID and gender columns; a bank account beyond its last 4 digits                                                                                                                                                                                                    |
| Read by                | The mapping wizard proposes a mapping from a sample, HR approves it, and a file connector imports the whole export through it (A-5)                                                                                                                                        |

**Open questions:** which company joins first, and through which system ([A-23](assumptions.md)); its tenant configuration (A-12).

## Trying a client's sample export

We asked the client for structure-only samples: headers, code lists, blank templates and a few dummy rows ([Q-50](client/questions-for-client.md)). When one arrives through the team's data folder, try it on a throwaway stack, so that nothing of it outlives the test:

1. **Check what it holds.** If the file holds real personal data, do not try it. Delete your copy and tell the team lead, who has it removed from the data folder and tells the client the same day ([handling confidential material](client/questions-for-client.md#handling-confidential-material)).
2. **Keep the AI on the mock.** Leave `LLM_PROVIDER` at `mock`, the default. A real model would receive the file's column headers, value shapes and up to eight distinct codes from each category column, and the client has not agreed to that ([Q-42](client/questions-for-client.md), and "No onward sharing" on the same page). AI coding agents never open the file either.
3. **Start a throwaway stack.** Stop your usual stack with `docker compose stop`, which keeps its data. Then start another under its own project name, with the override that publishes only the web app, on this machine's loopback address, and leaves the employee master empty:

   ```sh
   docker compose -p huitong-samples -f docker-compose.yml -f infra/docker/compose.samples.yml up --build --detach
   ```

   It has its own database and Redis volumes, so nothing reaches your usual database, and no other machine can reach it. Open `http://localhost:8080` in a private browser window.

4. **Try the file.** Update your branch from main first, so that git ignores the file: `git check-ignore -v samples/<file>` names the `/samples/*` rule. Copy the file into [`samples/`](../samples/README.md), propose a mapping from it in the mapping wizard, then stage it on the new file connector's page and sync it. The proposal, the preview and an apply keep the file's headers and values in that stack's database, the append-only audit log among them.
5. **Delete everything.** Close the private window, delete the file from `samples/`, and remove the throwaway stack with its volumes:

   ```sh
   docker compose -p huitong-samples -f docker-compose.yml -f infra/docker/compose.samples.yml down -v
   ```

   `docker compose start` brings your usual stack back. Take no screenshots on the throwaway stack, and never copy a value from the file into an issue, a pull request, a document or an AI prompt.

Git ignores everything in `samples/` except its README, and Docker builds leave the folder out. The pre-commit hook refuses a commit that would add a file there, the pre-push hook refuses a push whose commits hold one, and CI fails a pull request in which any commit holds one. A pushed branch is public, though. If a sample ever reaches GitHub, tell the team lead at once and follow the steps for a pushed sample under [R-03](grs/grs-by-design.md#data-breach-r-03): a new commit or a force-push alone does not take it off GitHub.
